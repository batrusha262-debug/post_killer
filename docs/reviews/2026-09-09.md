# Rust / Flutter review — 2026-09-09

Reviewed the five Rust crates, handwritten Flutter libraries, existing tests,
bridge boundary and packaging workflows. Generated FRB files are excluded from
manual decomposition; public Rust/FFI signatures and database schema are unchanged.

## Fixed findings

| Priority | Finding | Resolution / evidence |
| --- | --- | --- |
| P1 | Closing a request tab reconstructed state and reset the execution guard, allowing overlapping execution and lost response state. | Preserve unrelated state via nullable-aware copyWith; ignore late results for closed tabs. Regression test holds an execution open while closing its tab. |
| P1 | Different asynchronous workspace operations could interleave and append a collection to the wrong selected workspace. | One sequential storage-event queue covers bootstrap, selection and creation. Delayed-repository regression test covers cross-event ordering. |
| P1 | Updating a folder could create an ancestor cycle or leave descendants in another collection. | Transactional recursive ancestor and reverse-link validation; rejected updates leave the original folder intact. |
| P1 | Streaming execution could wait forever on a live but stalled event receiver, including terminal delivery after cancellation. | Bound execution including channel backpressure and terminal delivery by configured timeouts. Terminal delivery can return Timeout if the consumer does not drain; guaranteed delivery is impossible with a stalled receiver. |
| P2 | API-key query auth duplicated a key explicitly provided in the URL. | Explicit URL query takes precedence, matching existing explicit field/header policy; request-builder regression test. |
| P2 | Nullable copyWith fields could not clear stale errors or tab selection. | Explicit null is distinguished from omitted arguments. |
| P2 | Search hid empty collections even when their names matched. | Preserve name matches independently of request count; regression test. |
| P2 | Update checks could run concurrently. | Ignore repeated events while checking; delayed-repository regression test. |
| P2 | Buffered and streaming paths duplicated request building and could diverge. | Shared request builder, auth and body encoding; both paths tested against a local server. |
| P3 | Workspace screen, transport and bridge files mixed unrelated responsibilities. | Independent reusable Flutter components; Rust transport types, streaming, request construction, variable resolution, DTO conversions, SQLite history and tests extracted. |
| P3 | Unused Cupertino font dependency and obsolete repository documentation. | Removed dependency and lockfile entry; corrected documentation. |
| P3 | Local app version defaults diverged from release version. | Flutter package and updater fallback aligned to 0.2.3. |

## Remaining product gaps and follow-up findings

These are not claimed fixed by the refactor:

- Request cancellation is available in Rust streaming but not exposed through
  the current Dart execution port. Closing a tab ignores the result; transport
  remains bounded by its request timeout. Add a versioned cancellation contract
  and desktop integration tests (existing QA-007).
- Saved request CRUD/history/auth/environment UI wiring is incomplete. The
  production collection gateway returns no requests; request drafts remain local.
- Workspace FFI storage initialization caches its first failure until restart.
  A retryable initialization policy needs isolated filesystem-failure tests.
- Updater HTTP client lifetime is not explicitly disposed by the app provider.
- Manual workflow_dispatch packaging derives version from a branch name;
  tag-triggered releases use a proper version. Give manual runs a validated
  version input before treating manual packaging as supported.
- Signing/notarization, secrets storage and desktop E2E remain existing backlog.
